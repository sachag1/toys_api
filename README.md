# Toys API - תיעוד

**קוד המקור:** https://github.com/sachag1/toys_api

שרת REST API למערכת צעצועים, בנוי ב-Node.js עם Express ו-MongoDB.
המערכת מאפשרת למשתמש רשום להוסיף צעצוע, לערוך אותו ולמחוק אותו,
ולכל אחד לשלוף מידע על הצעצועים שנמצאים במסד הנתונים.

## התקנה והרצה

```bash
npm install
```

יש ליצור קובץ `.env` בתיקיית השורש לפי הדוגמה שבקובץ `.env.example`:

```
MONGO_DB=mongodb+srv://USER:PASSWORD@CLUSTER.mongodb.net/toys
TOKEN_SECRET=putYourOwnSecretWordHere
```

**קובץ ה-`.env` לא עולה ל-GitHub** - הוא מופיע בקובץ `.gitignore` יחד עם `node_modules`.

הרצת השרת:

```bash
npm start
```

השרת עולה על `http://localhost:3001`

מילוי המסד ב-12 צעצועים לדוגמה (3 קטגוריות, ריצה חד פעמית):

```bash
node json/seedToys
```

## מבנה הקולקשנים

### קולקשן `toys`

| מאפיין | סוג | הסבר |
| --- | --- | --- |
| `_id` | ObjectId | מזהה אוטומטי של מונגו |
| `name` | String | שם המוצר |
| `info` | String | תיאור המוצר |
| `category` | String | שם הקטגוריה |
| `img_url` | String | כתובת תמונה, לא חובה |
| `price` | Number | מחיר |
| `user_id` | String | המשתמש שהוסיף את הצעצוע, נלקח מהטוקן |
| `createdAt` | Date | נוצר אוטומטית על ידי `timestamps:true` |
| `updatedAt` | Date | נוצר אוטומטית על ידי `timestamps:true` |

### קולקשן `users`

| מאפיין | סוג | הסבר |
| --- | --- | --- |
| `_id` | ObjectId | מזהה אוטומטי של מונגו |
| `name` | String | שם המשתמש |
| `email` | String | **unique** - לא ניתן להירשם פעמיים עם אותו מייל |
| `password` | String | מוצפן ב-bcrypt, אף פעם לא מוחזר ללקוח |
| `role` | String | `USER` כברירת מחדל, או `ADMIN` |
| `createdAt` / `updatedAt` | Date | `timestamps:true` |

## אימות משתמשים - טוקן

הראוטים של **הוספה, עריכה ומחיקה** של צעצוע דורשים טוקן.

את הטוקן מקבלים מהראוט `POST /users/login`, ושולחים אותו בכל בקשה
מוגנת ב**הדר** בשם:

```
x-api-key: <הטוקן שהתקבל>
```

תוקף הטוקן הוא 60 דקות. הבדיקה מתבצעת בפונקציית middleware בקובץ
`middlewares/auth.js`, והמזהה של המשתמש נשמר ב-`req.tokenData._id`
כדי לשייך את הצעצוע לבעליו.

## ראוטים של משתמשים

### `POST /users` - הרשמה

יוצר משתמש חדש. הסיסמה נשמרת מוצפנת ב-bcrypt.

**Body:**

```json
{
  "name": "Sacha",
  "email": "sacha@example.com",
  "password": "123456"
}
```

**תשובה (201):**

```json
{
  "_id": "66d1f2...",
  "name": "Sacha",
  "email": "sacha@example.com",
  "password": "*****",
  "role": "USER",
  "createdAt": "2026-09-01T10:00:00.000Z"
}
```

**שגיאות:**

| קוד | מתי |
| --- | --- |
| 400 | הבאדי לא עבר ולידציה של Joi |
| 400 | המייל כבר קיים במערכת (`code: 11000`) |

---

### `POST /users/login` - התחברות

**Body:**

```json
{
  "email": "sacha@example.com",
  "password": "123456"
}
```

**תשובה (200):**

```json
{ "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }
```

**שגיאות:**

| קוד | מתי |
| --- | --- |
| 400 | הבאדי לא עבר ולידציה |
| 401 | המייל לא נמצא במערכת |
| 401 | הסיסמה לא תואמת |

---

### `GET /users/userInfo` - פרטי המשתמש המחובר

**דורש טוקן** בהדר `x-api-key`.

מחזיר את פרטי המשתמש ללא הסיסמה.

## ראוטים של צעצועים

בכל הראוטים שמחזירים רשימה, מוצגים **10 צעצועים בעמוד**.
הקווארי `?skip=` הוא **מספר העמוד** ולא מספר הרשומות:
`?skip=0` הוא העמוד הראשון, `?skip=1` הוא העמוד השני וכן הלאה.

---

### `GET /toys` - כל הצעצועים

```
GET localhost:3001/toys
GET localhost:3001/toys?skip=1
```

הראוט הזה מקבל גם את הקוואריז של החיפוש, הקטגוריה וטווח המחירים
(**בונוס - איחוד הראוטים**), כך שאפשר לשלב ביניהם:

| קווארי | הסבר | דוגמה |
| --- | --- | --- |
| `?skip=` | מספר העמוד | `?skip=1` |
| `?s=` | חיפוש ב-`name` או ב-`info` | `?s=wooden` |
| `?category=` | שם הקטגוריה | `?category=puzzles` |
| `?min=` `?max=` | טווח מחירים | `?min=100&max=300` |

דוגמה לשילוב - פאזלים במחיר של עד 80 שקלים:

```
GET localhost:3001/toys?category=puzzles&max=80
```

**תשובה:** מערך של אובייקטים.

---

### `GET /toys/search?s=` - חיפוש

```
GET localhost:3001/toys/search?s=robot
GET localhost:3001/toys/search?s=robot&skip=1
```

החיפוש מתבצע במאפיין `name` **או** במאפיין `info`, באמצעות ביטוי
רגולרי עם הדגל `i` כך שאין הבדל בין אותיות גדולות לקטנות.

---

### `GET /toys/category/:catname` - לפי קטגוריה

```
GET localhost:3001/toys/category/wooden
GET localhost:3001/toys/category/electronic?skip=1
```

---

### `GET /toys/prices?min=&max=` - טווח מחירים

```
GET localhost:3001/toys/prices?min=100&max=300
```

משתמש באופרטורים `$gte` ו-`$lte` של מונגו.
אפשר לשלוח רק `min`, רק `max`, או את שניהם.

---

### `GET /toys/single/:id` - צעצוע אחד

```
GET localhost:3001/toys/single/66d1f2a4b8c9d0e1f2a3b4c5
```

מחזיר **אובייקט בודד** ולא מערך.

| קוד | מתי |
| --- | --- |
| 404 | לא נמצא צעצוע עם ה-id הזה |

---

### `GET /toys/count` - מספר הרשומות

```
GET localhost:3001/toys/count
```

**תשובה:**

```json
{ "count": 12 }
```

---

### `POST /toys` - הוספת צעצוע

**דורש טוקן** בהדר `x-api-key`.

**Body:**

```json
{
  "name": "Wooden Train Set",
  "info": "A 40 piece wooden train set with rails",
  "category": "wooden",
  "img_url": "https://images.pexels.com/photos/1148998/pexels-photo-1148998.jpeg",
  "price": 149
}
```

המאפיין `user_id` **לא נשלח בבאדי** - השרת לוקח אותו מהטוקן ומוסיף
אותו לרשומה בעצמו.

**תשובה (201):** אובייקט הצעצוע שנוצר.

| קוד | מתי |
| --- | --- |
| 400 | הבאדי לא עבר ולידציה של Joi |
| 401 | לא נשלח טוקן, או שהטוקן פג תוקף |

---

### `PUT /toys/:id` - עריכת צעצוע

**דורש טוקן**. אפשר לערוך **רק צעצוע שהמשתמש עצמו הוסיף** -
העדכון מתבצע לפי `_id` **וגם** לפי `user_id` שנלקח מהטוקן.

```
PUT localhost:3001/toys/66d1f2a4b8c9d0e1f2a3b4c5
```

הבאדי זהה לזה של ההוספה.

| קוד | מתי |
| --- | --- |
| 400 | הבאדי לא עבר ולידציה |
| 401 | אין טוקן / הצעצוע לא שייך למשתמש הזה |

---

### `DELETE /toys/:id` - מחיקת צעצוע

**דורש טוקן**. כמו בעריכה, אפשר למחוק רק צעצוע ששייך למשתמש.

```
DELETE localhost:3001/toys/66d1f2a4b8c9d0e1f2a3b4c5
```

| קוד | מתי |
| --- | --- |
| 401 | אין טוקן / הצעצוע לא שייך למשתמש הזה |

## קודי שגיאה

| קוד | משמעות |
| --- | --- |
| 200 | הבקשה הצליחה |
| 201 | רשומה חדשה נוצרה |
| 400 | הבאדי לא תקין (Joi) או מייל כפול |
| 401 | בעיית אבטחה - אין טוקן, טוקן לא תקין, או הרשומה לא שייכת למשתמש |
| 404 | הכתובת לא קיימת, או שהרשומה לא נמצאה |
| 502 | שגיאה בצד השרת מול מסד הנתונים |

## סדר עבודה מומלץ לבדיקה ב-Postman

1. `POST /users` - להירשם
2. `POST /users/login` - לקבל טוקן
3. להעתיק את הטוקן להדר `x-api-key`
4. `POST /toys` - להוסיף צעצוע
5. `GET /toys` - לראות שהוא נוסף
6. `PUT /toys/:id` ואז `DELETE /toys/:id`
